Show the live camera preview.

Provide:
- Start camera
- Capture photo
- Retake photo
- Use this photo
- Cancel camera

Stop all camera media tracks when the camera is closed,
the user leaves the camera screen, or the component unmounts.

Handle these cases:
- Camera permission denied
- Camera unavailable
- No camera found
- Unsupported browser
- Camera initialization failure

Explain that camera access generally requires HTTPS
or localhost in supported browsers.

Never activate the camera without a user action.

If camera access fails, allow image upload as a fallback.

On mobile, also provide an option to use the device's
native camera through a file input with capture="environment".

Do not assume every browser supports the same camera behavior.

==================================================
5. TEXT EXTRACTION FROM IMAGES
==================================================

Implement OCR so the app can extract readable text
from uploaded images and captured photographs.

Use a suitable browser-compatible OCR library,
such as Tesseract.js, if it can be integrated reliably.

Keep OCR processing local where feasible.

Display a processing indicator:

"Reading your image..."

Show OCR progress if supported.

After extraction, display the extracted text in an
editable text area.

Allow the user to correct spelling, dates, names,
and other OCR mistakes before analysis.

Do not silently replace the extracted text with invented text.

If OCR fails:
- Show an error message.
- Keep the image preview available.
- Let the user enter the text manually.
- Allow them to retry.

If the image contains no readable text, explain that
the app could not extract enough text to analyze it.

Do not claim to support handwriting or every language
unless the OCR configuration actually supports them.

==================================================
6. AI POSTER UNDERSTANDING
==================================================

After OCR extraction, analyze the text and image context.

Use local analysis rules by default.

If an AI vision model is configured, allow the user
to explicitly choose AI image analysis.

Before cloud image processing, disclose that the image
will be sent to the configured AI provider.

Never expose API keys in frontend code.

Create a structured result containing:

A. POSTER SUMMARY
Explain the poster in two or three simple sentences.

B. MAIN PURPOSE
Identify whether it appears to advertise an event,
announce a deadline, provide instructions, or communicate
another purpose.

C. IMPORTANT HIGHLIGHTS
Extract the most relevant information.

D. DATE AND TIME
Identify event dates, registration deadlines, examination
dates, and other time-sensitive information.

E. LOCATION
Extract the venue or location when available.

F. WHO SHOULD CARE?
Identify the intended audience when the poster makes it clear.

G. REQUIRED ACTION
Explain what the reader may need to do next.

H. ELIGIBILITY
Extract eligibility criteria and requirements if mentioned.

I. CONTACT AND REGISTRATION
Extract contact details, registration instructions,
and URLs visible in the text.

J. MISSING OR UNCLEAR DETAILS
Point out important details that are absent or ambiguous.

K. SIMPLE EXPLANATION
Explain the poster in easy-to-understand language.

L. NEXT STEPS
Provide practical suggestions based only on the information
available.

Clearly distinguish extracted facts from AI interpretation.

Do not invent deadlines, registration links, locations,
or eligibility conditions.

==================================================
10. PRIVACY AND SECURITY
==================================================

Keep OCR processing local where feasible.

Display whether the image is being processed locally
or sent to a cloud AI provider.

Ask for consent before any cloud upload.

Do not upload an image just because the user selects it.

Do not store sensitive images unnecessarily.

Do not log image contents or extracted private text.

Revoke temporary object URLs when no longer needed.

Validate files before processing.
